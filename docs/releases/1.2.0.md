# Core 1.2.0 — development, not published

Additive Epic #1 interfaces build on immutable core-v1.1.0. All five packages use
1.2.0 for development; no existing consumer artifact, pin or deployment changes.

- AI runtime accepts an optional `usagePort.invoke` around each provider invocation.
  The default starter composes the public metered provider with a PostgreSQL store.
- SDK failures retain observed partial usage, request ID and model provenance for
  both streamed and buffered OpenAI paths; hidden SDK retries remain disabled.
- Typed metrics preserve missing, zero, estimate, synthetic and provider sources.
  Counts and fixed-scale currency amounts are separate from user billing.
- Starter migration 3 adds calls and deduplicated observation history, with tenant
  isolation, recovery evidence and per-operation summaries. It makes the legacy
  display token column nullable; old rows keep their historical value.
- The default route uses operation fingerprints and frozen quotes for new calls,
  preserving fixed 2-credit success and legacy result replay.
- Public fixed-operation pricing and billing adapter separate product configuration
  and result persistence from the ledger. Decisions use the persisted quote and
  exact policy version, with ownership and authorization checks.
- Execution budgets check the prepared prompt and freeze provider/model paths,
  output limits, retries and deadlines. Migration 4 persists resource holds and
  unknown external execution status; concurrent calls cannot bypass the budget.
- Migration 5 adds canonical fulfillment, decisions and independent financial
  status. The settlement store supports no-charge success, atomic result/ledger
  persistence and terminal replay; uncertain commits require reconciliation.
  Runtime failures use durable state through the new optional billing failure port.
- Public token pricing freezes input/output user rates and bounded reservations,
  aggregates before rounding once, audits usage references, and defers missing or
  over-authorized charges through the same billing adapter.

Consumers of existing public ports need no migration unless adopting the new
starter operation/usage persistence. Installation never executes SQL. Historical
ledger display values are not evidence of complete provider usage. Application
token policy composition and recovery workers are tracked in the remaining
Epic #1 stages; this is not a production release announcement.
