# Core 1.5.0

Adds the opt-in `options.outputTokenPolicy: 'provider_default'` configuration to
ai-engine's OpenAI Responses transport. `streamProviderText`,
`streamOpenAIResponses` and OpenAI `generateProviderText` omit SDK
`maxOutputTokens` and the wire `max_output_tokens` field in this mode. The public
`resolveMaxOutputTokens` returns `undefined`; do not persist that return value as
a JSON option. Persist the explicit policy instead.

Without the new policy, existing absent/null/zero, numeric/default and cap
behavior is unchanged. Provider-default mode ignores `maxOutputTokensDefault`
and requires `maxOutputTokens` and `maxOutputTokensCap` to be unset, including
no explicit null or zero. Conflicting fields and unknown policy values fail
explicitly before invoking the provider. Anthropic does not support this mode.
Provider/model limits and gateway defaults still apply; omission does not promise
unlimited generation or a cost bound.

Frozen-budget text executions reject any explicit output-token policy during
preflight, before metered invocation or durable usage writes. Their numeric
output holds, deadlines and accounting remain unchanged. The transport keeps
`maxRetries: 0`, `store: false`, caller cancellation, completion/protocol checks
and its 2 MiB decoded-text safety limit. That text limit is not a limit on raw
SSE frames, reasoning data or all response metadata. Products retain their own
timeouts, abnormal-output protection and content validation.

All five packages use the coordinated 1.5.0 version; only ai-engine behavior
changes. No SQL migration, pricing change, product opt-in or deployment occurs
on installation. Consumers pin verified immutable artifacts and separately test
their product. Roll back the policy's product adoption together with any core
downgrade: older releases do not understand the new option and can apply their
legacy default cap instead.

Offline tests cover public resolver compatibility, both OpenAI call paths, actual
SDK wire omission via intercepted fetch, conflicts, unsupported providers,
retained stream protections and budget preflight. A disposable PostgreSQL test
checks rejected opt-in creates no usage call and ordinary bounded execution
still proceeds. No real provider sampling is required by this change. Release
evidence belongs on the reviewed source PR before publication.
