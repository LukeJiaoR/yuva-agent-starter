# Core 3.0.0

Coordinated five-package release preparation for the audit #89 fixes merged in
#90. These release notes are not publication evidence; verify the authenticated
release/tag and immutable assets independently.

## Package changes

- billing-core preserves immutable usage allocations and subtracts only posted,
  actually restored support-refund credits from net consumption during payment
  revocation. Expired refunds do not falsely reduce consumed credits.
  It does not repair historical false-debt rows or compensate past balances;
  historical reconciliation requires a separate reviewed plan.
- Administrative credit deductions persist operation identity, canonical input
  and historical results; identical retries replay once, changed input conflicts,
  and legacy ambiguous deductions require reconciliation. Caller-owned transaction
  clients are protected by savepoints and must be used sequentially.
- ai-engine preserves statusCode/retryable classification and avoids copying raw
  provider/database exception messages or codes into default logs.
- auth-core rejects malformed claim-token expiry/TTL and handles sensitive-key
  casing, nested sensitive objects and prototype-shaped keys safely.
- admin-core and context-engine share the coordinated version; versioning alone
  does not imply a runtime change in every package.

## Breaking schema and protocol requirement

Node.js >=24.22.1 <25 remains required. Consumers invoking the existing
`deductAvailableCredits` API now require a `credit_mutations` table with the
contract in starter migration 008. A 2.0.0 consumer without that table cannot
perform a package-only upgrade for this API. Repository release policy defines
an incompatible schema requirement as a major-version change. This coordinated 3.0.0 release follows that policy; do not treat it as a
package-only backwards-compatible patch. Stop old application, admin and recovery
writers before the product migration and switch writers together. Do not mix the
old deduction path with the new durable mutation protocol, and do not roll back
to old writers without a separately reviewed recovery plan.

The starter manifest lists migrations 1–9. Migration 008 adds credit mutation
identity; 009 orders application-owned chat messages. Package installation runs
no SQL, and consumer-owned schemas must use their own migration history and
reviewed schema changes. A package rollback does not undo database migrations.
Ziwei requires its own migration and real administrative-deduction regression
before this complete five-package bundle can be admitted.
