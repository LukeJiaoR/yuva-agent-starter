# Core 1.4.0

Adds the opt-in `startFreeFeatureUsage`, `completeFreeFeatureUsage` and
`failFreeFeatureUsage` APIs to billing-core. A server-owned policy explicitly
authorizes a zero-price execution. These APIs preserve usage identity, frozen
price, transactional result completion, failure/cancellation/limited outcomes,
replay and controlled recovery without creating allocations or ledger entries.
The pure `readFreeUsageBalance` projection excludes expired buckets without
posting expiry as a side effect of free execution. Debt remains an admission
restriction. Normal Credit reservation and settlement still require positive
values and refuse free usage requests.

Consumers own claim/source authorization, result schema, admission/cost limits,
usage facts and SQL migrations. Opting in requires `pricing_strategy='free'`
and `failed`, `cancelled`, `limited` terminal usage states in the consumer schema.
Existing paid lifecycle, prices, OperationStore and starter composition are
unchanged. Installation does not migrate a consumer database or enable free
features. Roll back new admissions with a compatible application version;
do not install a version that cannot understand persisted free requests.

`starter-app/tests/freeFeatureUsage.test.js` verifies no financial mutations at
zero, signup, purchased and expired balances, concurrent idempotency, rollback,
debt, explicit recovery, immutable pricing and isolation from paid APIs on
disposable PostgreSQL. Release evidence is recorded on the reviewed source PR.
